## 上下文

当前 `simple_live_app` 中的安卓端播放器存在多个手势和显示问题：
1. 双击全屏功能无法正常工作
2. 非全屏放大后，音量/亮度手势的识别区域基于放大后的画面坐标，而非窗口坐标
3. 非全屏放大后，音量/亮度提示条随画面一起缩放和移动
4. 全屏模式下放大功能不生效

这些问题源于手势识别逻辑和 UI 渲染逻辑在处理画面变换（transform）时的坐标计算不一致。

## 目标 / 非目标

**目标：**
- 修复双击全屏功能，使其在任意播放状态下正常工作
- 修正手势识别区域计算，始终基于窗口坐标而非画面坐标
- 修正提示条位置计算，使其固定在窗口边缘，不受画面变换影响
- 确保全屏模式下放大功能正常工作

**非目标：**
- 不改变现有手势交互的基本模式（如滑动方向、触发区域大小等）
- 不添加新的手势类型
- 不涉及 iOS 端的修改

## 决策

### 决策 1：手势识别区域基于窗口坐标
**选择：** 手势识别时，将触摸点坐标直接映射到窗口坐标系，而非画面坐标系。

**理由：** 当前实现使用画面坐标系导致放大后手势区域偏移。窗口坐标系是稳定的参考系，不受画面缩放影响。

**替代方案：**
- 方案 A：在手势处理前逆变换画面坐标 —— 增加计算复杂度，容易出错
- 方案 B：限制放大后手势区域 —— 降低用户体验

### 决策 2：提示条使用 Overlay 独立渲染
**选择：** 音量/亮度提示条使用 Flutter Overlay 独立渲染，位置基于窗口边缘计算，不参与画面变换。

**理由：** 当前提示条是播放器画面的子组件，导致继承变换矩阵。独立渲染可确保位置稳定。

**替代方案：**
- 方案 A：在提示条上应用逆变换 —— 复杂且性能开销大
- 方案 B：将提示条移到播放器外部的布局层级 —— 需要重构布局结构

### 决策 3：双击检测使用 GestureDetector 的双击回调
**选择：** 使用 Flutter GestureDetector 的 `onDoubleTap` 回调处理双击事件。

**理由：** Flutter 内置的双击检测已经过优化，能正确处理事件冲突和时序。

**替代方案：**
- 方案 A：手动实现双击计时器逻辑 —— 增加维护成本，容易有边界情况
- 方案 B：使用第三方手势库 —— 增加不必要的依赖

## 风险 / 权衡

**风险 1：** 修改手势识别逻辑可能影响其他手势（如单击暂停、长按快进）
→ **缓解措施：** 全面测试所有手势交互，确保回归测试覆盖

**风险 2：** Overlay 渲染可能导致提示条与播放器其他 UI 元素的层级冲突
→ **缓解措施：** 使用合适的 OverlayEntry 插入位置，确保层级正确

**风险 3：** 不同 Android 版本或设备可能有触摸事件处理差异
→ **缓解措施：** 在多个设备和 Android 版本上进行测试
